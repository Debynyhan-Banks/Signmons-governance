# BE-003 — Eternity webchat backend production readiness

## Ticket

- ID: `BE-003`
- Repo: `signmons-calldesk-backend`
- Screen ID: `SCR-CUST-006`
- Integration surface: embedded assistant on `eternityhvacr.com`
- Backend endpoint: `POST /api/integrations/webchat/triage`
- Priority override: approved by the product owner on August 28, 2026; `FE-013` is paused and returns to `Next`.

## Objective

Make the CallDesk backend safe, reproducible and contract-ready for a staged Eternity Mechanical Services webchat pilot without connecting or deploying the public website in this ticket.

## In scope

- Repair clean-clone install/build behavior, Prisma generation and the missing architecture gate.
- Reconcile the legacy three-table migration history with the canonical multi-tenant Prisma schema while preserving legacy tables for later migration review.
- Remove hardcoded pricing, generic upselling and undisclosed-human-representation behavior from the default AI and tenant prompts.
- Add deterministic life-safety escalation before generative responses.
- Add a server-to-server webchat endpoint protected by a tenant-bound hashed integration credential; never accept tenant identity from the request body.
- Add DTO, authentication, tenant-isolation, safety, contract and database integration tests.
- Clear critical production dependency advisories and restore build, lint, test, architecture and audit gates.
- Document the exact website proxy contract and deployment prerequisites.

## Out of scope

- Connecting or publishing the Eternity website.
- Direct browser access to a backend secret.
- Appointment guarantees, autonomous diagnosis, prices, payments, SMS or automatic dispatch.
- Enabling generative responses in production before a tenant record, approved Eternity instructions, OpenAI key, database, integration credential and human escalation owner are configured.
- Migrating legacy production data into the canonical schema; legacy tables must be retained intact for a separate reviewed migration.

## Acceptance criteria

- [x] `npm ci` produces a usable Prisma client without requiring a real database secret.
- [x] Canonical migrations build a fresh database and retain legacy tables in a dedicated schema.
- [x] `POST /api/integrations/webchat/triage` requires a valid server-held bearer credential and derives `tenantId` from the credential mapping.
- [x] Direct browser integration and tenant identity in request bodies are unsupported.
- [x] Life-safety phrases return deterministic emergency guidance without calling the AI provider.
- [x] Default prompts disclose automation, avoid diagnosis, avoid unapproved fees and avoid default upselling.
- [x] Production configuration fails closed for database, admin credential, identity and webchat credential errors.
- [x] Production dependency audit reports no critical vulnerabilities.
- [x] Required gates pass: build, lint, unit/integration tests and architecture check.
- [x] The backend repository remains the only implementation repo changed by the ticket; governance changes contain only contract, pointer and evidence alignment.
