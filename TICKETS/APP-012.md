# APP-012 - Payment Gate and Webhook Status Workflow

## Ticket Summary

- Ticket ID: `APP-012`
- Repo: `signmons-calldesk-backend` (+ frontend app surface)
- Screen IDs: `SCR-APP-006A`, `SCR-APP-006B`, `SCR-APP-006C`, `SCR-APP-023`, `SCR-CUST-002`
- Objective: operationalize payment-first booking with deterministic gate enforcement and webhook-status transparency.

## In Scope

- Payment link/deposit request management.
- Basic fail-closed Stripe payment-before-booking enforcement for Starter and every higher paid plan when the tenant's governed policy requires a booking fee or deposit.
- Advanced Growth-and-higher controls for configurable deposits, service-fee preauthorization, exception approvals, partial-payment policy, and payment recovery.
- Payment status and webhook event tracking:
  - paid
  - failed
  - expired
  - refunded/canceled
- Booking policy gate status:
  - booking unlocked/locked
  - required fee rules
- Customer payment/deposit status page.

## Out of Scope

- Storing card PAN data in Signmons systems.
- Processor-internal dispute lifecycle UI.
- Full accounting export workflows.

## Acceptance Criteria (must all pass)

- [x] Payment links and deposit requests can be created and tracked.
- [x] Webhook status is visible and fail-closed on validation errors.
- [x] Booking gate enforces tenant policy before dispatch readiness.
- [x] Starter can enforce a required booking payment; the implementation does not reserve the basic gate for Growth.
- [x] Growth-and-higher advanced payment controls are separate entitlements and do not weaken Starter's basic fail-closed gate.
- [x] Customer payment status is viewable via secure link.
- [x] Payment and gate actions are audit logged.
