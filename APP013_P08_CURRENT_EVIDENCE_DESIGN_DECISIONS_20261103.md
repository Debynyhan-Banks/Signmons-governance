## Findings and recommended decisions

1. **Runtime expectation: reuse the existing approved structural rules, then bind the exact current environment digest.** The original legacy/controller.py305–309 obtains CUSTOMER_PAYMENT_RETURN_URL from the normal revision, validates it, then adds it dynamically to PLAIN_ENV. auth/reuse/controller.py218–235 independently requires11 literal safety settings,7 exact version1 secret references and that return URL:19 names total. The corrected October28 operation approved111b3d2 records this correction and its historical successful match. Do not use the historical observed digest as a new expected configuration or forget the dynamic field. A future producer must validate exact name cardinality/uniqueness, literal values, secret reference shapes and approved URL rules before digesting the exact environment list. Reuse the environment-specific logic; do not invoke the entire historical classify_cloud on retired traffic because it requires an active candidate tag. The existing required URL rule is HTTPS with host, no credentials/query/fragment; no new hostname/path criterion is silently added. The original copying provenance is historical, not proof of present equality to the normal revision. Duplicate names or conflicting value/valueFrom must stop rather than disappear in a dict conversion.

2. **Transport: recommend reusing the existing SDK/psql boundaries for the future full producer, with a separately reviewed SDK behavior exception before external execution.** NativeIO currently uses owner/config/auth commands and SDK metadata reads; SQL uses hidden administrator input, verify-full TLS, pinned endpoint/identity, application name and timeouts. The narrow cached-only adapter does not implement all current-state cloud/Firebase/SQL contracts. Replacing every SDK call with new HTTPS translations materially expands implementation. Local integration can exercise existing boundaries without external authority. A future exact external packet must disclose and bound SDK retry/cache/credential behavior; one command is not one provider request. No exception, renewal or permission is inherited from the consumed renewal. If no acceptable exact exception can be established, stop and present the cached-only alternative before implementing it. Never silently fall back between transports or request a password before source/readiness/authority are complete.

3. **Effective access: explicitly distinguish entry prerequisites from post-restoration usable access.** authority.py requires effectiveAccess=true before entry. The actual coordinator.py150–170 first restores runtime, then installs the exact temporary lookup/signing bindings, then requires four fresh CAN_ACCESS diagnostics; authentication follows under its separate existing gates. Requiring restored-runtime usable access while also requiring those bindings absent would mix different phases. Proposed meaning of the entry field: current owner capability for the exact authorized operations, exact roles/services/retired bindings and no unresolved entry-phase access denial. It must NOT certify future runtime authentication or signing/exchange success. Keep existing post-binding four-diagnostic and actual authentication checks mandatory; no UNKNOWN converted to true and no broad all-true fixture accepted as current evidence. This phase-specific meaning requires explicit owner agreement before implementing the producer; it is not an assertion that the existing generic field already enforces it.
