## Model contract

- CustomerConsentBrowserTransport is unregistered and opens no listener. Its four modeled POST paths are /customer-session/start, /capture, /prompt and /respond under the same prefix. These are fixture/model paths, not additions to the deployed API matrix.
- Require explicit canonical origin and tenant binding. HTTPS is required; only an explicit fixtureLoopback option permits HTTP at 127.0.0.1 with a port and loopback socket peer. No environment loader, wildcard, dynamic Origin reflection, Referer fallback, proxy-header authority or public integration credential.
- Require verified webchat_integration server context for the bound tenant, no impersonation, and server-supplied TLS/socket information. Browser headers cannot establish this context. The future BFF must verify its own server-side integration credentials; no automatic tenant selection.
- Exact Host and Origin must match the binding. Require Sec-Fetch-Site:same-origin, fetch mode cors or same-origin, Sec-Fetch-Dest:empty, X-CallDesk-Request:customer-intake-v1 and Content-Type:application/json. Missing/null/same-site/cross-site origins, navigation, cookies, public Authorization/Proxy-Authorization and content encoding refuse. GET/OPTIONS and query/trailing-slash/encoded-path variants refuse; no Access-Control-Allow-* or Set-Cookie response.
- The fixed custom header is a CSRF defense, not a secret or customer credential. These checks protect the browser boundary; non-browser clients can forge browser headers, and same-origin script compromise is outside this protection. Non-start operations additionally verify the customer credential's tenant before invoking the existing capture/prompt/response model. Those services retain all signature/session/marker/current-state checks.
- Raw headers are bounded (100 pairs, 8 KiB aggregate, 4 KiB each), duplicate names/control characters refuse. Body accumulation and final buffer are capped at 16 KiB. Fatal UTF-8 decoding, compact JSON.stringify-compatible JSON and exact per-operation fields refuse malformed/duplicate-key/ambiguous input. Whitespace-formatted JSON and charset content-type variants are deliberately unsupported in this local protocol.
- Fixture JavaScript uses fixed relative URLs, fetch mode cors, credentials:omit, cache:no-store and referrerPolicy:no-referrer. Mode cors preserves the real Origin for a same-origin POST under no-referrer; it does not authorize cross-origin requests. Browser tests require bootstrap success plus independent hostile-origin refusal.
- The budget port is required and fails closed for missing, denied, malformed or throwing admission. LocalCustomerBrowserBudget is a single-process, single-binding model: fixed 60-second windows, 60 total requests/10 starts, 20 per peer/5 starts, four in-flight leases and bounded peer storage. Socket peer is not taken from X-Forwarded-For. Failed admitted requests consume quota; release is idempotent and never refunds counts. Window rollover retains in-flight ownership; invalid/backwards monotonic clocks refuse.
- Local budget resets on process restart and is not shared across replicas. No durable/distributed limiter or network-level abuse protection is implemented. Production budgets, trusted proxy/IP normalization, header/socket/body deadlines and infrastructure-level errors require review before activation.
- All modeled outcomes carry private/no-store headers, no-referrer, nosniff, same-origin resource policy and restrictive JSON CSP. Successful results are explicitly projected: only bootstrap token/expiry, capture status, authenticated private prompt fields or a recorded status. Internal evidence/scope IDs and extra service properties are omitted. Every error has fixed text; diagnostics receive only fixed operation/status. No request body/header/path/mailbox/token/error object is logged by this model.
- No automatic request retry. Diagnostic/release failures cannot convert a committed service result into a second write. Browser completion clears private text and in-memory tokens. Unknown outcomes retain the prior same-unexpired-session retry/new-scope rules; this transport does not recover appointments or renew credentials.

## Release blockers unchanged

No production controller/module/route, BFF deployment, TLS/proxy trust, secret loader/key rotation, distributed limiter, access-log/analytics acceptance, cookie session or production collection is enabled. Outer framework/proxy/parser errors and existing global exception logging are not made safe merely by this inactive model; verify them before mounting it. The illustrative fixture has bounded HTTP headers/body/timeouts, but is not production infrastructure acceptance.

Full credential-bound AI intake, marker/old-writer and retention compatibility, dedicated mailbox fingerprints, verification, grant lifecycle/event-time binding, expiry/admission, durable delivery and existing Calendar/pre-finalization release risks remain. No live provider, queue, email/SMS send, production migration or release action. APP-013 stays sole Now; Next is unassigned.

## References

The strict Origin/Fetch Metadata/custom-header approach follows [OWASP CSRF prevention guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). This is a selected local protocol, not a claim of complete OWASP compliance. Client Origin behavior: [Fetch Standard](https://fetch.spec.whatwg.org/#append-a-request-origin-header) and [MDN Referrer-Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy).

Browser QA corrected an initial empty-string header assumption: the wire token is Sec-Fetch-Dest:empty, as specified by [W3C Fetch Metadata](https://www.w3.org/TR/fetch-metadata/#sec-fetch-dest-header). The server still refuses missing/incorrect metadata; the real-browser bootstrap assertion now catches incompatible client/header changes directly.
